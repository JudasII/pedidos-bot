In the ordering assistant I'm building, the language model never decides which product the customer ordered. A deterministic resolver does. This milestone was about building that piece.

Customers write "hamburgesa sensilla" (misspelled), "unas papitas familiares" or "malteda de chocolate". The resolver normalizes the text, looks for exact aliases, then the longest alias contained in the phrase, and finally does fuzzy matching with a threshold and a minimum gap over the runner-up.

The rule I cared about most: **never guess**. If someone says "a beer", it returns the three options so the bot asks. If someone just says "onion", it doesn't turn it into "no onion": mixing up "with" and "without" is exactly the mistake that costs the cashier the most.

Before writing tests, I probed 47 realistic phrases against the menu. Four failure modes showed up that I wouldn't have predicted — including a generic category word shadowing a typo of a specific product. Each one now has a fix and a test.

Then the code review proved me wrong: "papas sencillas" (small fries) became a burger, because the resolver trusted the longest alias and ignored the other words. Single items passed; real phrases didn't. Now a phrase only resolves when one reading explains its words, otherwise the bot asks.

Result: 172 green tests, 102 of them for the resolver, and a second restaurant config that guarantees no menu data is written into the code.
