# LinkedIn draft — Milestone 3 (EN)

> Can be published on its own or folded into a later post. Kept as a record.

My ordering assistant no longer loses an order if the process dies halfway through.

Every customer message is now one PostgreSQL transaction: state, reply and order commit together or not at all. Duplicate messages are dropped, and a repeated "yes" can't create a second order. Replies go through an outbox with retries, so a crash after confirming doesn't lose the message. If a customer comes back three hours later, the bot asks before going on; a day later, it offers the old cart with current prices.

The moment that stuck with me wasn't in the code I shipped. My test fixture wipes the database between tests, and its default port belonged to another project running on my machine. A port conflict stopped it before anything ran. Now tests use a separate database, and the fixture refuses to touch any database whose name doesn't end in `_test`. A destructive tool needs its own guard, not just a correct default.

Result: 526 green tests, plus 19 against real PostgreSQL. The in-memory fake and the real database run the same contract tests.
