# LinkedIn draft — Milestone 0 (EN)

> Not published on its own: it will be summarized and folded into the milestone 2 or 3 post, once decisions are backed by results. Kept as a record.

I started a side project: an assistant that takes burger-restaurant orders over chat. In many neighborhood restaurants in Colombia, 100% of orders arrive over WhatsApp, and whoever answers the chat is also running the register.

Before writing any logic, I made the most important decision: how to split the work between the language model and the code.

The obvious idea was a stage-based state machine (items → address → payment) with the LLM extracting data at each step. The problem: people write "2 plain burgers, one without onion, a large coke, to Calle 10, paying cash" in a single message. A stage that only expects items loses the rest.

I went with a different design: the LLM only translates the message into a list of actions (add item, set address, payment method...), and the code validates against the menu, computes the total and decides what to ask next. The model never invents products or prices.

Another lesson: I tested the secret scanner with a fake token, and the version I had pinned didn't catch it. Without that test, I would have assumed I was protected.

Milestone 0 result: a public repo with CI, guards for secrets and real data, 3 documented architecture decisions and 34 issues planned across 9 milestones.
